1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
The Dogfood 2026 Hackathon Platform was built to solve the premier engineering
challenge: "Build the platform that will judge you." This acceptance report 
verifies that the platform satisfies all functional and non-functional requirements
for orchestrating high-stakes 72-hour engineering hackathons without external cloud 
dependencies or third-party SaaS lock-in.

The platform provides a complete 5-stage lifecycle state machine, a dual-engine 
scientific judging system (weighted rubrics + Bradley-Terry Elo duels + Z-score 
normalization), 11 purpose-built interactive views, Server-Sent Events (SSE) 
real-time telemetry, 3-role persona switching, and 1-command Docker deployment.

3. DETAILED FUNCTIONAL ACCEPTANCE FINDINGS
--------------------------------------------------------------------------------

3.1 HACKATHON LIFECYCLE & STATE MACHINE (AC-01, AC-02, AC-03)
- Validated state transitions across:
  REGISTRATION -> TEAM_BUILDING -> SUBMISSION -> JUDGING -> RESULTS
- Verified that PATCH /api/hackathon/phase rejects unauthorized or invalid stage
  names with HTTP 400 and properly records an audit log entry.
- Verified that currentPhaseEnd countdown calculates remaining hours, minutes,
  and seconds accurately with real-time UI progression indicators.

3.2 DUAL-ENGINE SCIENTIFIC JUDGING (AC-04, AC-05, AC-06, AC-07)
- Weighted Rubric Scoring:
  Tested 5 criteria: Innovation (25%), Technical (30%), UI/UX (20%), 
  Self-Hostability (15%), Documentation (10%). Verified weighted average logic
  in calculateRubricScore().
- Z-Score Normalization:
  Verified normalizeScoresAcrossJudges() standardizes evaluations per judge:
  Z = (RawScore - JudgeMean) / JudgeStdDev
  Mapped into a 0-100 scale: 50 + (16 * Z), clamped between 0 and 100.
  Confirmed that a harsh judge giving a 5/10 (where their mean is 5.0) and a
  lenient judge giving an 8/10 (where their mean is 8.0) are calibrated equally.
- Pairwise Bradley-Terry Elo Duels:
  Verified updateEloRatings() with K=32. Equal opponents yield +/- 16 points.
  Underdog wins yield larger Elo rewards (+25 to +30) and favorite upsets lose
  equivalent points.
- Composite Score Blending:
  Confirmed final leaderboard score equals:
  (NormalizedScore * 0.70) + ((Elo / 16) * 0.30).
  Rankings are sorted descending and numbered sequentially without gaps.

4. NON-FUNCTIONAL & OPERATIONAL VERIFICATION
--------------------------------------------------------------------------------
- Self-Hostability: Zero external cloud services required (no Firebase, Supabase,
  PostgreSQL, Redis, or Auth0). Runs completely in a single self-contained unit.
- Containerization: Multi-stage Dockerfile builds client in Alpine Node 20 and
  serves statically from Express in runner stage.
- Non-Root User: Container switches to 'node' user for security compliance.
- Health Probes: /health returns HTTP 200 with uptime and status info, satisfying
  Docker and Kubernetes health check requirements.
- Design System: Pure vanilla CSS implementation (index.css) with CSS custom
  properties, high-contrast Obsidian dark theme, and micro-interactions. Zero Tailwind.
